# RentNest Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build RentNest, a polished Android equipment-rental marketplace demo where one app serves customers (browse → book → rent → review) and providers (inventory by unit, booking requests, check-out/return, earnings), running fully offline on seeded data.

**Architecture:** Single Gradle module `app` (package `com.rentnest.app`) in MVVM. Pure-Kotlin `domain` layer (models, rule engines, repository interfaces) → `data` layer (Room + DataStore implementations, seed data) → `ui` layer (Jetpack Compose screens: stateless `XContent` composable + `XScreen` wrapper + Hilt `XViewModel` exposing `StateFlow<UiState>`). UI depends only on domain interfaces.

**Tech Stack:** Kotlin 2.1.21, AGP 8.11.1, Gradle 8.14.3, JDK 21, Jetpack Compose (BOM 2025.06.01) + Material 3, Navigation Compose 2.9.1 (type-safe routes via kotlinx.serialization), Hilt 2.56.2 + KSP, Room 2.7.2, DataStore Preferences 1.1.7, JUnit4, kotlinx-coroutines-test, Turbine, Robolectric 4.15.1.

**Spec:** `docs/superpowers/specs/2026-10-07-rentnest-design.md`. Read it before starting any task.

## Global Constraints

- Package / applicationId: `com.rentnest.app`. App name "RentNest" lives only in `res/values/strings.xml` (`app_name`).
- `minSdk = 26`, `compileSdk = 36`, `targetSdk = 36` (android-36 is the only installed platform).
- Build JDK: JDK 21 (Homebrew `openjdk@21`), pinned through `org.gradle.java.home` in `gradle.properties`. The system Java 25 is too new for this toolchain.
- If a pinned dependency version fails to resolve or the versions turn out incompatible, bump to the nearest stable versions that work together. Record the change in that task's commit message. Never downgrade `minSdk`/`compileSdk`.
- Money is stored as `Long` **paise** everywhere. Display goes only through `MoneyFormatter` as ₹ with Indian digit grouping (₹1,23,456).
- Dates are `java.time.LocalDate`. Booking `endDate` is **inclusive**. Material date pickers use UTC millis; convert only through `DateMillis`.
- The demo user id is `DEMO_USER_ID = 1L`. This user is both a customer and the owner of provider id 1.
- REQUESTED bookings never reserve stock. Only ACCEPTED and ACTIVE bookings do. A unit's "rented" state is derived from ACTIVE bookings, never stored.
- No network, no real payments, no real auth. All images are drawn in code by `ItemArt` (gradient + category icon), so the app works offline. This replaces the spec's mention of Coil: nothing needs to load bitmaps, so Coil is not added.
- Fonts: Plus Jakarta Sans (headings) and Inter (body), bundled as variable TTFs in `res/font`.
- Customer accent: deep teal (`#00695C` light / `#53DBC9` dark). Provider accent: warm amber (`#9A5B00` light / `#FFB866` dark). The earnings chart bar color is `#9A5B00` light / `#C77C1E` dark; both values were checked with the dataviz palette validator.
- Touch targets ≥ 48dp. Every icon-only button has a `contentDescription`. Status is never shown by color alone (icon + label).
- Commit after every task. Use Conventional Commit prefixes, and end every commit message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Gradle commands run from the project root: `./gradlew ...`. Unit tests: `./gradlew testDebugUnitTest`. Single class: `./gradlew testDebugUnitTest --tests "com.rentnest.app.<Class>"`.

## Review Focus

1. **Booking ranges that span a fully booked day or start in the past.** The date picker disables single days, but a range can still straddle a booked day. `requestBooking` must refuse with `DatesUnavailable` / `InvalidDateRange` and create nothing. Covered in Task 8 (`requestRejectsRangeSpanningFullyBookedDay`, `requestRejectsPastStart`).
2. **Timezone off-by-one from date pickers.** The device is likely on IST (UTC+5:30). Converting picker millis to `LocalDate` must not shift the day. Covered in Task 2 (`DateMillisTest`, which round-trips under a non-UTC default zone).
3. **Degenerate items.** `weeklyRate = 0`, zero units, or all units in maintenance must not price a rental at ₹0 or crash. The item must show as unavailable. Covered in Task 3 (`zeroWeeklyRateFallsBackToSevenTimesDaily`) and Task 4 (`noUsableUnitsMeansNothingBookable`).
4. **Provider retires or services a unit that a customer has already been promised.** Moving an AVAILABLE unit to MAINTENANCE/RETIRED while it has an ACCEPTED (not yet ended) or ACTIVE booking must be refused with `UnitBusy`. Covered in Task 8 (`updateUnitRefusesWhenUnitHasAcceptedBooking`).
5. **Double-tap on Pay creates two bookings.** A second `pay()` while processing or after success must be a no-op. Covered in Task 14 (`payTwiceCreatesOneBooking`).
